# 國際扶輪 3523 地區活動整合報名系統 (Rotary District 3523 Event Registration SPA)

本專案為國際扶輪 3523 地區年度常態活動之整合報名系統單頁應用程式 (Single Page Application, SPA)，專為扶輪社各社執秘、社長、主委與地區幹部設計，支援各作業系統與行動裝置連動。

---

## ✨ 系統核心功能

1. **✍️ 各社執秘專用工作區**
   - 內建 3523 地區 1~13 分區各扶輪社標準名冊庫。
   - **⛳ 高爾夫差點 (Golf Handicap) 整合庫**：維護社友資料時支援登記 0~54 高爾夫差點，勾選自動帶入報名表，即時動態計算全隊平均差點。
   - 一鍵勾選免重複 Key-in，自動帶入職務、Nick Name、葷素需求。
   - 防竄改社別鎖定機制。
   - **🎁 贊助獎登錄**（運動賽事）：執秘可直接點選本社社友（如總監、地區賽事主委、地區秘書長）登錄贊助獎，可選「現金（填金額）」或「禮品（填名稱）」並勾選是否用餐；勾選用餐者自動列入用餐人數與葷素統計，免餐費、不計入該社應繳總計；同步顯示於 LINE 通報、主委儀表板、名單明細與 Excel 匯出；主委「全部展開（合併 Excel/CSV）」檢視、複製全體名冊與 Excel 另有「全體贊助獎彙整」，不分社集中列出並附合計。

2. **📊 當屆主委戰情儀表板**
   - **🗂️ 收合式面板，新手主委也看得懂**：主委後台與最高權限管理頁的每個區塊預設收合，標題下方一句白話說明「點開可以做什麼」，想看再按「展開」；展開狀態會記在該裝置，另有「全部展開／全部收合」。最上方固定顯示報名人數、葷素、贊助金額、封存狀態四格總覽。
   - 即時報名人數、葷食/素食、贊助累計金額統計。
   - 針對「地區高爾夫球聯誼賽」自動切換選手差點戰情報表。
   - 各社已提交報名明細與出席名單（含差點）一鍵展開檢視。
   - 模擬活動當日 00:00 自動封存唯讀機制。
   - **🧹 正式上線前資料歸零（最高管理員）**：最高權限管理頁提供「清空繳費紀錄」「清空全部報名單」「清空全部社友庫」三顆歸零按鈕，皆需二次確認、清空後所有裝置同步；另有「載入示範資料」供展示用。系統啟動時不再自動生成模擬繳費資料。
   - **🏢 地區辦公室不列入繳費名單**：「地區辦公室」僅供指派為活動主委（地辦人員協助後台），繳費總表、催繳名單、投影模式與 Excel 匯出皆以 80 社計算，不含地區辦公室。
   - **💳 繳費狀況依子活動分開**：各分區各社繳費狀況即時總表以「子活動」為單位各自一張（GMS、DTLS、年會大會…互不影響），應繳金額自動帶入該子活動的「各社應繳金額」；執秘送出報名表不會自動標記為已繳費，由主委手動核訖或貼上銀行通知核對。
   - **🔒 主選單與子活動增刪僅限最高管理員**：「新增/刪除主選單」、「新增/刪除子活動」四個按鈕只有最高管理員登入後才會顯示，活動主委與各社執秘進入時完全看不到，也無法操作。
   - **📎 活動DM（海報／簡章）上傳**：主委在「活動設定與費用金額」面板點開「活動DM」，可上傳 PDF、JPG、PPT／PPTX（每檔最大 20 MB，可多檔），各社執秘在報名頁標題下方會看到「📎 活動DM」連結可開啟或下載；每個子活動各自一組檔案，主委可刪除舊檔。檔案存放於 Supabase Storage（需先依下方「活動 DM 檔案空間設定」建立一次）。
   - **💳 匯款帳號與上海商銀入帳通知自動對帳**：主委在「活動設定與費用金額 → 匯款帳號與入帳通知信箱」填寫匯款帳號、銀行通知信寄達的信箱帳密與通知單 PDF 開啟密碼（戶名統編／身分證末六碼）；執秘在**每個活動**的報名頁都會看到匯款帳號、應繳金額（運動賽事等為本社報名表總計）與「匯款備註請填貴社全名（例：南區扶輪社）」提醒，**匯款後不需要另外回報**。雲端小程式每 10 分鐘讀取信箱中的上海商銀「入帳通知單」，解開加密 PDF 附件取出存摺備註與金額，依「備註中的社名＋金額」比對後自動標記「已繳費（Email 自動核對）」，執秘端同步顯示「✅ 已收到您的匯款」；主委可按「立即抓取」、檢視所有入帳紀錄，未配對的入帳可手動指定給某社。需先依下方「入帳通知自動對帳設定」完成一次設定。
   - **💰 各子活動獨立費用設定**：參賽選手費、只用餐費、共同主辦社/協辦社/贊助社金額、研習會每社應繳金額、社慶花款與餐費，皆依「子活動」分別儲存，高爾夫、保齡球、各社社慶可各自設定不同金額，互不覆蓋。

3. **📲 跨作業系統與手機行動端連動中心**
   - **動態 QR Code 掃碼**：使用 iPhone / Android 手機直接掃碼即可於行動端瀏覽器開啟。
   - **原生系統分享 (Web Share API)**：一鍵呼叫手機原生選單，直接轉發至 LINE、AirDrop 或各大 App。
   - **💬 LINE 扶輪一鍵通報**：針對台灣扶輪社溝通習慣，一鍵格式化產出出席名冊（含職稱、姓名、Nick Name、葷素、**高爾夫差點**）並直接開啟 LINE 傳送。執秘報名頁的「⚡ 行動快捷功能」列即有「📲 一鍵傳送到 LINE 群組」按鈕，手機點擊會直接開啟 LINE 選擇群組並帶入名冊文字；電腦需安裝 LINE 桌面版才會開啟，否則請改用「💬 複製 LINE 報名名冊」貼上。
   - **🤖 AI 小幫手**：執秘報名頁「⚡ 行動快捷功能」列的「🤖 AI 小幫手」按鈕會開新分頁到地區的 AI 問答系統（Agentic RAG），並自動帶入目前綁定的社名，輸入該系統的社密碼即可詢問「我們社報名了什麼、報了誰、繳費了沒、匯款帳號」等問題（AI 只能查詢自己社的資料，問其他社會被拒絕），也能查扶輪知識文件。網址設定在 `index.html` 開頭的 `RAG_ASSISTANT_URL`，留空則不顯示按鈕。
   - **📅 行事曆連動 (.ics & Google Calendar)**：支援匯出標準 `.ics` 檔案與一鍵加入 Google 日曆。
   - **💾 跨裝置備份與同步代碼**：本機 LocalStorage 自動持久化保存，支援一鍵產生同步字串代碼跨裝置貼上還原，以及 JSON 備份檔匯出/匯入。
   - **📥 跨平台無亂碼 Excel (CSV)**：採用 UTF-8 BOM (`\uFEFF`) 編碼，徹底根除 Windows 繁體中文 Excel 亂碼問題。
   - **PWA 行動端優化**：支援 iPhone「加入主畫面」全螢幕運行如原生 App。

4. **🔄 生命週期規格與 E-R Schema 檢視**
   - 清楚展示年度換屆資料銜接邏輯（清空當屆報名，但永久留存各社執秘社友資料庫與高爾夫差點）。

## 活動 DM 檔案空間設定（最高管理員只需做一次）

活動 DM 的檔案本體存放在 Supabase Storage 的 bucket `event-dm`。第一次使用前請在 Supabase 後台建立：

1. 登入 https://supabase.com/dashboard ，進入本系統的專案。
2. 左側選單點 **SQL Editor** → **New query**。
3. 貼上下面整段 SQL，按 **Run**：

```sql
-- 建立公開讀取的 bucket「event-dm」，單檔上限 20 MB，只允許 PDF / JPG / PPT / PPTX
insert into storage.buckets (id, name, public, file_size_limit, allowed_mime_types)
values ('event-dm', 'event-dm', true, 20971520,
        array['application/pdf', 'image/jpeg',
              'application/vnd.ms-powerpoint',
              'application/vnd.openxmlformats-officedocument.presentationml.presentation'])
on conflict (id) do update set public = true, file_size_limit = 20971520,
  allowed_mime_types = excluded.allowed_mime_types;

-- 前端用 anon key 直接上傳／讀取／刪除，所以要對 anon 開放 event-dm 這個 bucket
create policy "anon read event-dm"   on storage.objects for select to anon using (bucket_id = 'event-dm');
create policy "anon upload event-dm" on storage.objects for insert to anon with check (bucket_id = 'event-dm');
create policy "anon update event-dm" on storage.objects for update to anon using (bucket_id = 'event-dm');
create policy "anon delete event-dm" on storage.objects for delete to anon using (bucket_id = 'event-dm');
```

4. 看到 `Success` 即完成。回到系統，以主委身分在「活動設定與費用金額 → 活動DM」上傳一個檔案測試。
5. 若上傳時出現「雲端尚未建立 event-dm 儲存空間」或「存取權限尚未開放」的提示，代表上面的 SQL 沒有成功執行，請重新執行一次。

## 入帳通知自動對帳設定（最高管理員只需做一次）

這個功能需要三樣東西：① 雲端資料表與排程、② 讀信的雲端小程式、③ 收銀行通知信的信箱帳密與通知單 PDF 的開啟密碼。

### ① 建立資料表與每 10 分鐘排程

1. 開 https://supabase.com/dashboard/project/ncrvmhfggfczicpyebvn/sql/new 。
2. 把專案裡 `supabase/sql/bank_mail_setup.sql` 的整段內容貼上，按 **Run**，看到 Success 即可（可重複執行）。
   它會建立 `bank_transactions`（入帳紀錄，前端可讀）、`bank_mail_settings`（信箱與密碼，**前端只能寫不能讀**，密碼不外洩）、`bank_mail_status`（抓取狀態），並用 pg_cron 每 10 分鐘呼叫一次雲端小程式。

### ② 部署雲端小程式 `fetch-bank-mail`

在這台電腦的終端機（或 Claude Code 對話中用 `!` 開頭）依序執行：

```bash
supabase login                      # 會開瀏覽器登入 Supabase 帳號，登入一次即可
cd "/Users/fruit/Documents/insta360/01扶輪/3523報名表"
supabase link --project-ref ncrvmhfggfczicpyebvn
supabase functions deploy fetch-bank-mail --no-verify-jwt
```

`--no-verify-jwt` 是讓排程與前端都能直接呼叫；這支小程式只會「去讀信並寫入入帳紀錄」，不會回傳任何密碼或私人資料，且 20 秒內重複呼叫會自動略過。

### ③ 填入收通知信的信箱、密碼與 PDF 開啟密碼

上海商銀的入帳通知信**本文沒有金額**，入帳明細放在一個**加密 PDF 附件**裡，開啟密碼是帳戶戶名的「身分證號或統一編號末六碼」。所以後台要填三樣：信箱帳號、信箱密碼、PDF 開啟密碼。

1. 確認上海商銀的入帳通知寄到哪個信箱（網路銀行「服務類 → 電子郵件服務設定」可查看或變更）。
2. 以主委或最高管理員身分進「活動設定與費用金額 → 匯款帳號與入帳通知信箱」：
   - **信箱服務**：HiNet（ms○.hinet.net 結尾的中華電信信箱）直接選 HiNet，密碑用平常登入信箱的密碼即可。
     若是 Gmail：先到 Google 帳戶 → 安全性 → 開啟「兩步驟驗證」，再到 https://myaccount.google.com/apppasswords 建立一組 16 碼「應用程式密碼」，填這組而不是登入密碼。
   - **Email address**、**Email 密碼**。
   - **PDF 開啟密碼**：戶名的身分證號／統一編號末六碼（6 碼數字）。
3. 按「儲存信箱並測試連線」。幾秒後狀態列出現「掃描 N 封，其中銀行通知 N 封，新增入帳 N 筆」且沒有紅字就成功了；「③ 銀行入帳紀錄」會列出最近 60 天所有入帳。
4. 常見紅字：「信箱登入失敗」→ 帳號或密碼打錯；「PDF 開啟密碼錯誤」→ 末六碼不對；「連不上收信主機」→ 信箱服務選錯。
5. **HiNet 信箱要先關掉「海外登入限制」**：雲端小程式在國外的伺服器執行，HiNet 預設不允許非臺灣 IP 登入，會回「LOGIN failed. Invalid login/password.」（明明帳密正確）。到 https://webmail.hinet.net 登入 → 設定 → 環境設定 → 「登入來源限制設定」，把 **POP3/IMAP 的「不允許非臺灣 IP 登入」取消勾選** 後儲存（網頁郵件那一項可維持勾選）。
6. 第一次設定時信箱裡可能已累積幾十封通知，雲端每次只處理 4 封（平台 CPU 限制），按「立即抓取」會自動一輪一輪續抓到做完；之後排程每 10 分鐘抓一次，平常一天幾封不會有這個問題。

### 重新上傳雲端小程式（程式有更新時）

在 Finder 開啟專案資料夾，點兩下 **「部署雲端小程式.command」**，看到 ✅ 上傳成功即可（第一次若被 macOS 擋下，對檔案按右鍵 → 打開）。

### 比對規則（讓主委了解為何有些入帳要手動指定）

執秘匯款後不需要回報，系統只看銀行通知信上的「存摺備註」與「金額」：

- 存摺備註含有某一社的社名關鍵字（例如「南區」「松山」），且只對得上一個社（「西南區」不會被「南區」搶走）。
- 入帳金額正好等於該社某個**尚未繳費**活動的應繳金額：研討會／年會／分攤金＝主委設定的各社應繳金額；運動賽事、社慶等＝該社報名表的總計。
- 同一個主選單裡有多個同金額的未繳項目（例如上半年、下半年分攤金）→ 先沖銷排在前面的那一項。
- 同金額的未繳項目分散在不同主選單 → 系統無法判斷，留給主委指定。
- 其餘情況（備註空白、亂碼、金額不符）會留在「未配對」，主委在入帳紀錄右側選社別按「指定」即可。

## 社長當選人學習研討會 (PELS)：依出席方式收費與旅平險資料

子活動名稱含「PELS」或「社長當選人」時，系統自動切換成這個模式：

- **主委「活動設定與費用金額」**：不顯示「每社應繳金額」，改為四個費用欄位——① 本人單獨出席－2人1房（每人）② 本人與眷屬共同出席－2人房 ③ 本人單獨出席－指定住單人房 ④ 不克參加（需補課）請假理由。
- **先設定費用才開放報名**：四種出席方式的費用都還是 0 時，執秘端會顯示「主委尚未設定費用，暫不開放報名」且無法送出；主委填入金額並按「儲存主委設定」後立即開放。
- **執秘報名**：每位報名者選一種出席方式，費用自動加總為本社應繳金額；選「不克參加」要填請假理由。
- **旅平險資料**：出席者（含眷屬）必須填身分證字號、民國出生年月日、手機號碼，系統會檢查格式。＊個資僅用於旅平險。
- **個資保護**：身分證字號、生日、手機**不會**存進一般報名資料，也不會顯示在名冊、LINE 文字或任何畫面上；送出後連執秘自己也只看到「已送出」。主委要在「出席方式總覽與旅平險名單」面板輸入「個資檢視密碼」才能匯出 Excel 交給保險公司；活動結束後可在同一個面板刪除全部個資。
- **個資檢視密碼**：與登入密碼不同，第一次由主委或最高管理員在面板上設定（至少 8 個字），之後變更需輸入舊密碼。忘記密碼只能請系統維護人員到 Supabase 重設。

### 旅平險個資保存空間設定（每個地區的資料庫只需做一次）

到 Supabase → SQL Editor，把 `supabase/sql/insured_persons.sql` 整段貼上執行。沒有執行的話，PELS 報名送出時會提示「雲端尚未建立旅平險個資保存空間」而無法送出（刻意如此，避免個資被存到公開的地方）。

## 地辦分攤金／配合款：各分區繳款達成率圖表

主委（或被指派為主委的地區辦公室）進入「地辦分攤金/配合款」或任何名稱含「分攤金」「配合款」的子活動時，後台最上方會出現「各分區繳款達成率」圖表：

- 上方四格：全區達成率、尚未繳款社數、實收金額（對照應收）、全數繳清的分區數。
- 每個分區一條橫條：深色＝已繳款的社，灰色＝尚未繳款；右邊是達成率與「已繳社數／分區社數」。
- 橫條旁直接列出該分區**尚未繳款的社名**。
- 可切換「依分區順序」或「達成率低的在前」。
- 資料與下方的繳費總表完全同步，主委核訖後圖表立刻更新。
- 按「📄 匯出 PDF（簡報用）」會下載一頁 A4 橫式的「各分區繳款達成率報告」（含地區名稱、年度、項目名稱、資料時間、四格摘要、各分區達成率橫條、分區實收與未繳社名），可直接投影或放進簡報。排序方式跟著畫面上的選擇。第一次匯出需要網路（要下載 PDF 產生元件）。

## 貼上 LINE 接龍，自動勾選報名名單

社內通常先在 LINE 群組接龍，再由執秘報名。社友多時不必一個一個勾：

1. 在 LINE 群組長按接龍訊息 →「複製」。
2. 回到報名系統，在「○○扶輪社 社友庫」右上角按「💬 貼上 LINE 接龍」，把文字貼進框框（或按「從剪貼簿貼上」），再按「辨識名單」。
3. 系統會列出：**找到的社友**、**需要人工處理**的行（社友庫裡找不到這個名字，或同名無法判斷）、**略過**的行（取消／請假）。
4. 按「帶入報名表」，找到的社友就會全部勾選好。檢查無誤後按「送出本社報名表」。系統不會自動送出。

比對規則：

- 用社友庫裡的**中文姓名**或 **Nick Name** 比對，大小寫、全形半形、空白、連字號都不影響（`C-Wang`＝`C Wang`＝`CWang`）；Nick Name 前面的扶輪職稱（P、PP、PDG、PAG…）有寫沒寫都認得（接龍寫 `PAG LED`、社友庫登記 `LED`，或反過來，都對得上）。
- 「+1」「夫婦」「伉儷」「+夫人」會一併勾選該社友的寶(尊)眷（社友庫裡要先建好眷屬資料）。
- 運動賽事中，行內寫「只用餐」的社友會自動設成只用餐。
- 含「取消」「請假」「不克」的行會略過；若同一個人前面接龍、後面又寫取消，會從名單中拿掉。
- 接龍的標題、時間、地點等沒有編號的行會自動忽略。

## 活動報到（活動當天櫃台點名）

活動當天，櫃台工作人員用電腦、平板或手機開啟「報到頁」，在名單上點一下就完成報到。多個櫃台可以同時點名，彼此的結果幾秒內就會互相看到，不會蓋掉。

**哪些活動可以報到**：所有子活動都可以，不必另外設定；只有「分攤金／配合款」沒有報到（那只是繳款項目）。同一天的多個子活動（例如年會的大會與晚宴）各有自己的名單與報到網址。

### 主委：活動前與活動當天

1. 登入後切到該活動，在主委後台點開「🎫 活動報到」面板。
2. 按「設定報到密碼」（至少 4 個字）。這組密碼是給櫃台工作人員用的，請不要用貴社的登入密碼。
3. 把「報到頁網址」（可按「複製網址」，或讓工作人員掃面板上的 QR Code）與報到密碼交給工作人員。
4. 活動開始前按「▶ 開始報到」；結束後按「⏹ 結束報到」。只有「報到中」的時候櫃台才能點名，這樣網址就算外流也不會有人提前亂點。需要補登時可以再按「重新開始報到」。
5. 面板上會即時顯示應到、實到、未到、現場加報人數。
6. 「重新設定報到密碼」後，所有櫃台都會被退回輸入畫面，要用新密碼重新進入。
7. 「清空報到紀錄」只在活動前測試完、要歸零時使用，清空後無法復原。

### 櫃台工作人員：報到頁

- 開啟網址後輸入報到密碼與櫃台名稱（選填，例如「第一分區櫃台」，會記在每一筆報到紀錄上）。這台裝置會記住密碼，重新整理不必重打。
- **報到**：在搜尋框輸入姓名、Nick Name 或社名（大小寫、全形半形、空白都不影響），或用分區下拉選單找人，按「報到」。點錯可以按「取消」。
- 每個社的標題會顯示「已到／應到」人數，以及該社是否已繳費（尚未繳費會顯示金額，方便櫃台提醒）。
- 每個人會標示素食、參賽／只用餐、PELS 出席方式等，方便發餐券或資料袋。
- **現場加報**：沒報名卻到場的人按「➕ 現場加報」，選分區與社、輸入姓名（社友會出現在建議清單，名冊外的來賓直接輸入姓名即可）。加報時要選「已到」（加報並完成報到）或「還沒到」（例如社友先幫他報名：先加入名單，人到了再在名單上按「報到」；加錯可以按「移除」）。現場加報**只記在報到紀錄裡**，不會更動該社的報名表與應繳金額，費用請主委活動後處理。
- **統計分頁**：應到／實到／未到／現場加報、出席率、實到的葷素人數、各分區與各社明細。「實到」是現場實際人數，已包含現場加報；出席率只算有報名的人。各社名單會列出所有人（含現場加報），**紅色＝已報到**、灰色＝尚未報到；可「匯出 Excel」（報到明細、各社統計、各分區統計三個工作表）或「複製未到名單」貼到 LINE。
- PELS 的「不克參加」不列入應到名單；「攜眷」只點報名者本人，眷屬隨同報到（眷屬姓名屬於受保護的個資，不會出現在報到頁）。

### 請留意

- 報到頁只會「讀取」報名資料，不會修改任何報名表，所以櫃台裝置開一整天也不會影響各社的報名。
- 報到密碼只是避免無關的人誤入。本系統沒有真正的帳號登入，無法防止懂技術又刻意搗亂的人，防護程度與整個報名系統相同。
- 報到需要網路；現場網路不穩時，點名會顯示失敗並請您重試，不會默默遺失。

### 活動報到資料表設定（每個地區的資料庫只需做一次）

到 Supabase → SQL Editor，把 `supabase/sql/event_checkins.sql` 整段貼上執行（可重複執行；這份檔案有更新時再執行一次即可，既有報到紀錄不受影響）。沒有執行的話，主委後台的「活動報到」面板會顯示「雲端尚未建立報到資料表」，其他功能不受影響。

## 主委調整費用：已送出的報名表自動更新

主委在「活動設定與費用金額」修改費用（參賽費、只用餐、共同主辦／協辦／贊助社金額、社慶花款與餐費、研討會每社應繳金額、PELS 四種出席方式費用）後，這個活動**所有已送出的報名表**會自動依新費用重算應繳金額，各社不需要重新送出；繳費總表、匯款區塊的「本活動應繳」與自動核對入帳都會改用新金額，各社執秘開著的畫面也會即時更新。

- 分攤金／配合款是各社執秘自己填的金額，不會被重算。
- 已經核對為「已繳費」的社，金額變動後仍維持已繳費；系統會在提示中列出這些社，差額請主委另行處理。

## 多人同時使用：畫面自動更新（不需重新整理）

- 執秘按「送出本社報名表」後，自己的畫面直接更新；**主委如果正開著後台報名表，約 1 秒內會自動出現新的報名**，並跳出「○○扶輪社 剛送出報名表」提示，不需要重新整理網頁。
- 主委核訖繳費、上傳活動 DM、修改費用等，其他開著的畫面也會自動更新。
- 網路不穩漏掉通知時，系統每 15 秒會自己再檢查一次；手機從背景切回網頁時也會立刻檢查。
- 送出報名表前系統會先抓一次最新資料，避免兩個社同時送出時互相蓋掉。若沒有成功存到雲端，會跳出提示請您再按一次，勾選的內容不會消失。
- 主委正在後台輸入文字或開著彈出視窗時，畫面會等您輸入完才更新，避免打到一半被洗掉。

## 各社預設密碼與修改密碼

- 地區設定檔（`config/districts/<代號>.json`）的 `defaultClubPassword` 可以填一組「內定密碼」。有填的地區，所有社第一次都用這組密碼登入，登入畫面不再顯示「首次進入 (註冊)」。
- 執秘登入後，在報名頁的「⚡ 行動快捷功能」按 **🔑 修改密碼**：先輸入目前的密碼，再輸入兩次新密碼（至少 4 個字），就會改成自己的密碼。
- 執秘忘記密碼時，最高管理員到「最高權限管理」的密碼查詢卡片按「重置並清除此社密碼」，該社就會恢復成預設密碼。
- `defaultClubPassword` 留空的地區維持原本流程：各社到「首次進入 (註冊)」自行設定密碼。

## 地區設定（同一份程式給不同扶輪地區使用）

所有「地區專屬」的內容（地區名稱、年度、Logo、Supabase 連線、AI 小幫手網址、分區與社名冊）都不寫在 `index.html`，而是放在 `config/districts/<地區代號>.json`，由 `scripts/build-config.js` 轉成 `district-config.js` 給網頁讀取。

- 3523 的 `district-config.js` 已放在倉庫裡當預設值，所以直接開 `index.html`、GitHub Pages、現有 Vercel 專案都不需要額外步驟。
- 要改 3523 的名冊或年度：改 `config/districts/3523.json`，執行 `node scripts/build-config.js`，把產生的 `district-config.js` 一起 commit。
- 要給另一個地區用：複製 `config/districts/_template.json` 成 `<代號>.json` 填好，Logo 放 `assets/logo-<代號>.png`，在該地區的 Vercel 專案設定環境變數 `DISTRICT_CODE=<代號>`，部署時 `vercel.json` 會自動執行建置腳本換成該地區的設定。
- `supabaseAnonKey` 是可公開的 publishable 金鑰，資料安全靠 Supabase 端的 Row Level Security，不靠藏金鑰。
